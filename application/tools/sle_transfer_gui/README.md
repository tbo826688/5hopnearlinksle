# NearLink SLE 五跳文件透传平台

Windows 桌面工具，用于在以下链路上发送和接收文件：

```text
PC -> Node1 -> R1 -> R2 -> R3 -> R4 -> Node6 -> PC
```

## 功能

- 自动枚举 Windows COM 口
- 同一个 EXE 可切换发送端、接收端和双页面调试模式
- 波特率可编辑并提供常用预设，默认 `921600 8N1`
- 文件选择、保存目录和发送限速
- 发送端提供独立“建链模式”，逐跳显示 `Node1 → R1 → R2 → R3 → R4 → Node6`
- “链路速率测速”发送约 60 KB 随机校验数据，Node6 显示端到端有效接收速率
- 可切换“两跳验证模式”，只检测 `Node1 → R1双板桥 → Node6`
- 探测停在哪一跳会直接提示对应的板间链路，不需要接收电脑配合
- 实时进度、速度、剩余时间和状态日志
- 页面支持垂直滚动，适配高 DPI 和小尺寸窗口
- 接收文件先写入 `.part`，SHA-256 通过后生成正式文件
- 30 秒无新数据会结束等待并保留 `_incomplete` 文件，不再无限卡住
- 校验失败保留 `_checksum_failed` 文件，人工停止保留 `_interrupted` 文件，扩展名不变
- 接收页可直接“打开文件”或“打开目录”查看未完整文件
- 同名文件自动增加序号，避免覆盖
- 默认兼容已验证的 `V5HP` 电脑端协议
- 可选 `V5H2`，增加自动文件名和文件头 CRC
- 接收端同时识别 `V5HP` 与 `V5H2`
- 固件使用 64 包存储窗口、4～16 包动态拥塞窗口、累计 ACK、选择性 NACK 和 80～600 ms 自适应重传
- Node1 周期上报环形缓冲余量、动态窗口和重传超时，Node6 经 R4～R1 回传逐跳队列状态
- 默认“SLE闭环稳定260”保持 260 kbps 正常发送，仅在真实队列积压、信用耗尽或链路异常时短暂停写
- Node1 连续 5 秒无端到端 ACK 进展会主动重建链路；路由连续 5 秒无法向下游转发也会自动重连
- Node6 先把有序数据放入独立 64 KB 输出队列再确认，避免 USB 串口瞬时抖动阻塞无线接收
- 发送节奏提供“自适应间歇（推荐）”“固定间歇”和“连续自适应（兼容）”三种模式
- 自适应间歇以 4 个文件包为初始批量，每批保留 20 ms 排空间隔；拥塞时缩小到 2 包并把间隔增加到最高 100 ms
- Node1 缓冲恢复且未确认包持续较少时，程序会缓慢扩大批量、缩短间隔，避免突然升速再次压满五跳队列
- Node1 同时上报 UART 溢出计数，检测到新增丢字节时 GUI 会立即停止本次无效传输
- 建链探测会在 2.5 秒窗口内重复发送，固件在暂时无信用时保留探测包而不是丢弃
- 再次开始建链时，Node1 会主动清理未完成文件留下的发送窗口和会话状态，避免探测命令被当成残余文件数据
- 接收连续 10 秒无新数据时进入等待恢复状态，不再提前终止文件

## 固件要求

- Node1：`SLE UART Server` + `CONFIG_SAMPLE_FILE_TRANSFER_MODE`
- Node6：`SLE UART Client` + `CONFIG_SAMPLE_FILE_TRANSFER_MODE`
- R1~R4：Route Server + Client 双角色
- Node6 的数据 UART 在文件传输期间不能输出调试日志

两跳验证时，Node1、Node6、R1-RX、R1-TX 四种固件均需启用 `CONFIG_SLE_TWO_HOP_VALIDATION_MODE`，上位机链路拓扑选择“两跳验证模式”。完整五跳时保持该配置关闭。

## 直接运行

安装 Python 3.11 后，在本目录执行：

```cmd
py -m pip install -r requirements.txt
run_gui.bat
```

也可以直接运行：

```cmd
py app.py
```

## 使用顺序

1. 两台电脑运行同一个 `SLE-5Hop-Transfer.exe`。
2. 在连接 Node6 的电脑选择“接收端（Node6 电脑）”。
3. 选择 Node6 串口和保存目录。
4. 如果发送端使用默认 `V5HP`，填写接收文件名，例如 `received.mp4`。
5. 点击“开始监听”。
6. 在连接 Node1 的电脑选择“发送端（Node1 电脑）”。
7. 选择 Node1 串口和文件，确认两端波特率与固件一致，默认均为 `921600`。
8. 可先点击“开始建链”；发送端会逐跳显示 6 块板状态，连续 3 次全通后自动停止并释放串口。再次建链会重新发起独立探测。
9. 需要测速时，保持 Node6 监听，发送端点击“链路速率测速”；接收页显示的速率是端到端有效吞吐，不是芯片标称 PHY 空口速率。
10. 默认协议保持 `V5HP`；需要自动保留原文件名时，两端使用 GUI 并选择 `V5H2`。
11. 发送节奏建议保持“SLE闭环稳定260（推荐）”；普通文件点击“开始发送”，接收端显示 SHA-256 校验通过后再打开文件。

程序会记住最后选择的运行角色，并分别保存发送页和接收页的串口、波特率及文件路径。传输或监听进行中不能切换角色，防止串口任务被意外隐藏。

默认发送目标为 `260 kbps`。“SLE闭环稳定260”不再固定地“发一批、停一批”，而是依据 Node1 缓冲、动态窗口、R1～R4 转发队列、信用等待和 Node6 输出队列实时决定是否微停或排空。链路正常时持续按 260 kbps 写入；出现真实积压时暂停，连续恢复后自动继续。旧的连续、自适应间歇、固定间歇和峰值排空模式仍保留。

接收端连续 10 秒没有新数据时先显示“等待五跳链路重传恢复”；30 秒仍没有新数据则结束等待并把已有内容保存为同扩展名的 `_incomplete` 文件。若 SHA-256 不一致则保存为 `_checksum_failed`，人工停止或串口异常则保存为 `_interrupted`，这些文件不会再被自动删除。

建链探测由 Node1 发出，R1~R4 和 Node6 逐跳回报到 Node1，再由 Node1 串口显示在发送页。因此两台电脑分别连接端点时，发送电脑也能独立判断故障停在哪一跳。

文件业务数据仍是 PC 到 Node6 的单向流，但固件内部会让 Node6 经 R4、R3、R2、R1 向 Node1 返回小型 ACK/NACK 控制包。发送页的 100% 表示电脑已经把文件写入 Node1，最终成功仍以接收页显示 SHA-256 校验通过为准。

## 打包 EXE

双击：

```text
build_exe.bat
```

生成文件：

```text
dist\SLE-5Hop-Transfer.exe
```

单独构建闭环稳定版可双击：

```text
build_stable260_exe.bat
```

生成文件：

```text
dist\SLE-5Hop-Transfer-Stable260.exe
```

发送电脑和接收电脑使用同一个 EXE，在窗口右上角选择对应运行角色即可。“调试模式（双页面）”保留原来的双标签页界面，适合一台电脑同时连接 Node1 和 Node6 时使用。

## 协议兼容性

| 发送端 | 接收端 | 结果 |
|---|---|---|
| 旧 `send_file.py` (`V5HP`) | 新 GUI | 支持 |
| 新 GUI 默认 `V5HP` | 旧 `receive_file.py` | 支持 |
| 新 GUI `V5HP` | 新 GUI | 支持 |
| 新 GUI `V5H2` | 新 GUI | 支持，自动文件名 |
| 新 GUI `V5H2` | 旧 `receive_file.py` | 不支持 |

`V5H2` 只比 `V5HP` 多几十字节的一次性文件头，不影响五跳吞吐率。
