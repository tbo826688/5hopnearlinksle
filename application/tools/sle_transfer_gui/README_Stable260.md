# SLE闭环稳定260版

## 本版解决的问题

- 不再按固定大间隔盲目停发，链路正常时持续按 `260 kbps` 向 Node1 写入。
- Node1 上报 UART 缓冲、未确认包数、动态拥塞窗口和重传超时。
- Node6 每 `200 ms` 把 R1～R4 队列、信用等待、发送失败和接收异常逐跳带回 Node1。
- 上位机只在真实积压时微停；链路断开或严重积压时等待排空，恢复稳定后自动续传。
- Node1 或任一路由连续 `5 s` 无转发进展时主动重连，避免“显示已连接但永远不再走数据”。
- Node6 使用独立输出队列隔离 USB 串口抖动，已接收的数据不会因电脑短暂来不及读取而阻塞空口。

## 固件要求

本版增加了端到端状态帧和自动恢复逻辑，必须重新编译并烧录全部六块板：

1. Node1：`SLE UART Server`，启用文件传输模式。
2. R1～R4：选择 `SLE Route Server & Client`，在菜单中的 `Logical router id` 依次设置为 `1/2/3/4`。
3. Node6：`SLE UART Client`，启用文件传输模式。
4. 完整五跳必须关闭“两跳验证模式”。
5. Node1、Node6 数据串口均为 `921600 8N1`。

## 上位机运行

源码运行：

```cmd
py -m pip install -r requirements.txt
py stable260_app.py
```

生成独立 EXE：

```cmd
build_stable260_exe.bat
```

输出位置：

```text
dist\SLE-5Hop-Transfer-Stable260.exe
```

## 测试顺序

1. Node6 电脑先选择接收端、串口和保存目录，再点击“开始监听”。
2. Node1 电脑选择发送端，拓扑保持“完整5跳模式”。
3. 点击“开始建链”，等待 Node1、R1、R2、R3、R4、Node6 连续稳定全绿。
4. 发送节奏保持“SLE闭环稳定260（推荐）”，选择文件后点击“开始发送”。
5. 最终结果以 Node6 文件长度和 SHA-256 校验通过为准；发送页 100% 只代表电脑已写入 Node1。

## 现场观察

- `正常`：全链路队列低，持续按 260 kbps 写入。
- `轻度积压`：程序插入 2～8 ms 微停，让瓶颈队列下降。
- `排空保护`：链路状态缺失、队列过高或检测到丢包，暂时停止写入并等待恢复。
- `[FT Recovery]`：Node1 连续 5 秒没有端到端 ACK 进展，开始重建整条链路。
- `[Router Recovery]`：对应路由连续 5 秒无法向下一跳发送，开始重连该跳。

`260 kbps` 是本系统的应用层目标发送速率，不等同于芯片 PHY 标称速率。是否能在每跳 50 米环境稳定达到该值，仍需用同一文件连续多轮实测，以 Node6 有效吞吐和完整校验结果为准。
